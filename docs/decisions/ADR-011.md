# ADR-011 · Local transactional artifact storage

Status: Implemented for the bounded local workbench, 25 November 2026

## Context

The Rust-first design uses SQLite for authoritative state and SHA-256 addresses for evidence. ADR-002 describes a private blob store alongside the database. The first local workbench accepts small bounded artifacts and runs with one supervised worker.

## Decision

Store workbench artifacts and manifests as SHA-256-addressed SQLite BLOBs. Commit them in the same transaction as the attempt, metrics, accounting and audit event. Keep the native fixture's separate file layout and the frozen workbench protocol files. Preserve digest addresses in reports and the API independently of storage layout.

## Alternatives and review trigger

A sidecar blob store would keep database growth lower for large artifacts and add a crash reconciliation boundary for publishing records across resources. The bounded database representation keeps the initial SQLite write and restore path small. Measure storage growth and transaction latency before adopting a sidecar for larger or concurrent workloads. A migration must keep existing digests, evidence and verdict history readable.
