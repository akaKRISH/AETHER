# ADR-021 · Declarative, inert research skill registry

Status: Authorized local scope for APO-07 from `5f30f71`.

## Decision

Keep research skills as Rust-owned, versioned declarations in the existing SQLite model registry and content-addressed artifact store. A manifest pins a stable ID and semantic version, strict typed JSON input/output shapes, description and bounded instructions, closed capability allowlists, local model requirements, inference/resource budgets, evidence-reference requirements and exact `(id, version)` dependencies. Its SHA-256 identifies the serialized definition bytes. A changed definition requires a new version.

The five reviewed built-ins are literature review, hypothesis criticism, experimental design, development dataset qualification and model evaluation. Capabilities are default-deny and cannot express shell, Python, network, arbitrary code, training, verification or approval. Composition resolves pinned dependencies, detects cycles, and uses checked aggregate limits. A preflight receipt binds skill and dependency identities, trust/approval receipts, input digest, evidence references and requested resource budgets.

Imported declarations are inert and start untrusted. Only local CLI review and exact capability approval can advance their status; the authenticated API is read-only for registry authority and can create preflight records only. Even a reviewed or approved skill is never executed by this milestone. A model or instruction cannot change capability grants, approval, or verification authority. Evidence references are recorded and structurally checked, but source lookup and independent verification are not claimed. The user interface escapes the instruction text and marks it untrusted.

## Alternatives considered

- Executable plugin packages: rejected because code loading, update channels and isolation would add a distinct security and supply-chain system without a demonstrated need.
- General workflow engine: rejected because the five declarative skills need pinned dependency and budget preflight, not arbitrary dataflow execution.
- Reuse existing SQLite and artifact storage: selected to avoid parallel registry and identity mechanisms.

## Consequences and revisit conditions

The registry can describe capabilities and validate requests but does not perform research, call a model, check evidence existence, execute dependencies or produce skill outputs. Approval receipts are local operator records, not external signatures. Before any future executor, define a separately reviewed typed runner contract, per-capability implementation mapping, evidence-resolution rules, OS isolation, cancellation behavior and execution-specific approvals. Preserve this registry schema and add a versioned contract rather than making imported declarations executable.
