# ADR-004 · Trusted verification

Status: Proposed realization of the v0.2 verification invariant

## Context

A candidate is an interested party whose claims can be malformed or wrong.

## Decision

Evaluate accepted predictions against frozen rules and protected labels in trusted Rust. Require independent evidence where the protocol prescribes it. Only authorized verifier results can support a VERIFIED transition.

## Alternatives and trade-offs

Candidate-reported scores are cheap and provide no independent evidence. A human-only or model-scored rule can handle subjective work later, with a separate reliability and protocol review. Deterministic grading simplifies audit for initial computational tasks.

## Verification and review trigger

A forged candidate verdict and failed replay cannot verify a claim. Revisit evaluator methods by protocol version while retaining the trusted-verifier boundary.
