# ADR-005 · CPU-first native fixture

Status: Proposed realization of the owner’s CPU-first constraint

## Context

The development laptop and study budget favor cheap tests and straightforward replay.

## Decision

Begin with a fixed synthetic classification fixture in native Rust on CPU. Add a reviewed Python ML task pack after this checkpoint and its worker gate.

## Alternatives and trade-offs

The v0.2 charter’s planned Python-backed scientific baseline gives a richer task with dependency and evaluator risks. A GPU-first prototype increases availability and repeatability cost. The native fixture teaches ownership and metric invariants before those complexities.

## Verification and review trigger

Fresh build and repeat run on the supported CPU path without Python, GPU or model service. Revisit GPU use only after an applicable task shows measured benefit.
