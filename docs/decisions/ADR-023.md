# ADR-023 · Deterministic workflow composition through APO-09

Status: Implemented locally for APO-08; approval remains local operator consent.

## Decision

Represent research workflows as immutable, content-addressed DAG definitions in the existing SQLite registry and artifact store. A workflow pins exact reviewed skill versions and declares strict input/output schemas, field mappings, dependencies and aggregate limits. Validate pins, schemas, mappings, acyclicity and bounded graph depth before execution. Execute nodes sequentially in deterministic topological order.

The workflow layer is not an executor. Every node is submitted to the APO-09 kernel, which rechecks that skill's immutable digest, trust, current approval and revocation, typed input/output, capability intersection, limits and receipt. A workflow adds no capability field and cannot expand any skill's permissions. Its operator approval is content-addressed and binds the workflow digest and the exact skill approval receipt pins. Any changed workflow or skill approval invalidates that consent. The local receipt is not an external signature or security boundary.

Aggregate operation, input, output and dependency-depth budgets bound a run in addition to each APO-09 request. Receipts bind the workflow and skill pins, input/output digests, ordered node receipts, budget consumption and outcome. Replay reuses deterministic native operations and does not create a scientific verdict. Evidence remains `unverified` absent an independent authorized verifier.

The only built-in workflows are fixture definitions for literature review → hypothesis criticism, hypothesis criticism → experimental design, and the three-step chain. Approval and revocation stay in the local CLI; authenticated API routes are read-only for definitions and receipts, with execution requests allowed only through the same checks.

## Alternatives considered

- General-purpose workflow language, expressions, scripts or dynamic plugins: rejected; APO-08 needs a closed declarative DAG over registered native operation IDs.
- Parallel execution or automatic retry: deferred; neither is needed for this milestone, and both complicate ordering, cancellation and replay semantics.
- Execute workflow nodes directly: rejected; APO-09 remains the sole execution path and per-skill authority boundary.
- Add workflow-level capability inheritance: rejected; workflows must not grant or propagate permissions beyond APO-09.

## Consequences and limits

Execution is sequential. Cancellation is cooperative between synchronous native operations; an active operation is not hard-preempted. The implementation provides no OS isolation, unrestricted filesystem/network mediation or secure-sandbox guarantee. Workflow completion means only that the declared local operations completed; it does not establish research correctness, evidence verification or approval to conduct a campaign. Local fixture workflows do not execute real research campaigns.
