# ADR-022 · Bounded native skill execution kernel

Status: Implemented locally for APO-09 from the APO-07 registry.

## Decision

Keep immutable APO-07 `/1` declarations registered but inert. Publish executable built-ins as `/2` definitions with a required closed `OperationId`, exact input/output schema, exact required capabilities, no optional capabilities, and no model or inference budget. The operation enum is the complete dispatch allowlist; instruction text is never interpreted. A registered operation maps only to reviewed Rust code that reads the local literature catalog, proposes graph drafts, inspects a development dataset manifest, or reads an existing model evaluation report.

Execution pins `(id, version, sha256)`, validates the root and pinned dependency closure, and checks every local approval and revocation receipt. Dependencies are validated but not executed: the request authorizes exactly one root operation, with a maximum dependency depth of eight. Effective capabilities are the intersection of the root declaration, operator-approved set and operation-supported set. Input and output schemas, payload sizes, resource ceilings, operation count and cancellation are checked fail-closed. Content-addressed receipts record all resolved pins, approval receipt digests, operation version, input/output digests, budgets, evidence references and outcome.

Evidence references are shape-checked only and remain `unverified`. A local approval receipt represents operator consent in this installation; it is neither a signature nor a security boundary. The kernel does not call models or providers and does not execute shell, Python, JavaScript, downloaded code or plugin binaries.

## Consequences and limits

The versioned contract preserves old immutable definitions without silently granting them executable meaning. Operation limits and bounded underlying APIs constrain work, but cancellation is cooperative at operation boundaries. Synchronous native operations are not preempted by a hard timeout. The implementation does not provide OS-level isolation, unrestricted filesystem/network mediation, or a secure sandbox claim. A new operation or authority requires a reviewed enum variant, exact schema/capability contract, tests and a new operation version.

## Alternatives considered

- Execute instruction strings or imported code: rejected; instructions remain inert data.
- Execute every dependency in a workflow: rejected; there is no typed dataflow contract between existing skills, and APO-09 only authorizes one root operation.
- Upgrade old v1 definitions in place: rejected because definition digests and versions are immutable.
- Treat local approval receipts as cryptographic authorization: rejected; they are local consent records only.
