# ADR-019 · Adapter-training proposals and synthetic rehearsal

Status: Authorized by the owner for APO-06A from `ff48125`.

Rust validates split bytes, binds model identity to the inspected registry entry and publishes the typed manifest to the content-addressed evidence store. Compact JSON in Rust field order defines the manifest SHA-256. The host snapshot and approval status sit outside that hash. The existing model evaluator supplies the matched baseline checks. A training draft confers no campaign authority.

Each JSON Lines split has a pinned SHA-256, source declaration and curator. Validation rejects repeated IDs or normalized prompts and any source group shared between splits. Normalization folds case and whitespace. A separate declared test curator is a prerequisite for review. Exact overlap checks leave semantic similarities and pretraining exposure unresolved. Test data and paths stay on the controller side. The proposal retains only split hashes, counts, and provenance.

The planner supports FP16-base LoRA and NF4 double-quantized QLoRA with FP16 compute. For each target class, the adapter estimate multiplies rank by the sum of input and output widths and by the instance count. The memory model reserves 16 bytes per adapter parameter, includes simple activation and dense attention terms, and adds runtime headroom. Frozen-base storage is estimated at two bytes per parameter for LoRA or five-eighths for QLoRA with rounding. Storage includes the original weight file, datasets, retained checkpoints and a final adapter. A dense reference estimate uses six times base elements times padded tokens. Geometry and these estimates require backend and hardware qualification. [PEFT LoRA reference](https://huggingface.co/docs/peft/main/en/package_reference/lora) · [Transformers quantization reference](https://huggingface.co/docs/transformers/main/en/quantization/bitsandbytes)

The Rust `TrainingBackend` boundary emits typed checkpoint events. The Python wire contract accepts one bounded UTF-8 JSON job with schema `aether.training-worker-job/1`. Canonical job hashing sorts object keys recursively and uses compact JSON. The job carries the manifest digest, settings, caps, base identity and train/validation hashes. Checkpoints bind job hash, step and synthetic receipt hash. Atomically publish only adapter checkpoints in future qualified work. Bind any future resume to the same manifest and optimizer, RNG and data-order state. [Python protocol fixture](../../scripts/training_worker_fixture.py)

The executable backend in this milestone is synthetic. Rehearsal requires an explicit exact manifest digest and a stored synthetic base. Its receipts carry zero weight updates, an absent adapter artifact and unmeasured regression gates. There is no real launch route. Admission for future real training requires an independently reviewed and pinned worker and runtime, exact content approval, verified immutable base weights, qualified storage and compute limits, independently controlled test inputs, matched capability checks and a safety gate. GGUF is an inference artifact in this backend design. A SafeTensors shard alone still requires the complete trainable package and review. The CLI and API expose records without installing runtimes, downloading weights, changing a model or executing live training.
