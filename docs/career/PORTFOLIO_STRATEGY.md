# Portfolio strategy

Make each shipped milestone reviewable on a modest CPU. Keep the exact command, machine profile, input and evaluator identity, raw outcome and a plain-language explanation of the engineering decision. Link each claim to a test or measurement with scope and date. Check that links and reproduction permissions survive export.

| Milestone | Reviewable evidence |
| --- | --- |
| Genesis | Source inventory and validation audit, original ADRs, teaching notes and first-milestone acceptance criteria |
| First native checkpoint | Short CLI walkthrough, expected fixture metric, failure test transcript and explanation of Rust borrowing and error types |
| R0 follow-up | Reproduction from clean workspace, trusted evaluator, bounded reviewed worker and one controlled recovery record |
| R1 | Frozen study design, raw trial inventory, paired analysis with uncertainty, evidence bundle and named limitations |
| R2+ | Profile or operational drill supported by actual telemetry, explicit environment and approved publication scope |

Prepare a three-minute and a fifteen-minute walkthrough. Both should start with the research question, trace one claim from frozen protocol to verdict and show one failure with a measured or testable response. Label results as pending until a run produces evidence. Select reviewable artifacts from the [career alignment](CAREER_ALIGNMENT.md) map.
