# Release management

Release owners identify supported platforms, component compatibility, breaking changes, task-pack rights and benchmark limitations. Code versioning and schema versioning have separate histories. Before release, regenerate the runnable reproduction instructions, inventory required notices and verify asset digests. Record independent replay and all allowed failure modes.

Release only from a reviewed revision with approved distribution terms. Use tags, signatures or publishing only after owner authorization and key management decisions. [Release criteria](../roadmap/RELEASE_CRITERIA.md)
