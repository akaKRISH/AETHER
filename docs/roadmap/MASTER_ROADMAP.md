# Master roadmap

Phase progression follows verified deliverables and owner approval. Time indications in [v0.2](../archive/v0.2/AETHER/17_ROADMAP_LEARNING.md) are planning estimates. Keep each learning exercise small enough to explain at review.

| Phase | Entry condition | Deliverable and exit evidence |
|---|---|---|
| 0 Genesis | Imported brief available | Source archives, canonical design, audit, risks, and first lesson ready for owner review |
| 1 Foundation | Owner approves M1 and local toolchain qualifies | Native fixture CLI meets M1 acceptance, owner explains evaluator and replay |
| 2 Scientific evidence | M1 reviewed | Typed manifests, digests and SQLite graph/ledger; tamper and recovery tests pass |
| 3 Execution infrastructure | Evidence write path and exact dataset rights verified | One reviewed isolated worker, budget and recovery; denial, quota, replay and cancellation tests pass. Wider R0 local gate |
| 4 ECAR | R0 invariants and approved scheduling scope | Pure policy with reserve, deterministic ordering, dependency tests and synthetic decisions |
| 5 Intelligent research | Scripted policies pass and adapter approval recorded | Structured proposals from an approved adapter; identical policy regardless of source |
| 6 Research validation | Pilot ready, literature and protocol reviewed | Development pilot, sample size decision, frozen study, complete held-out results with independent replay. R1 gate |
| 7 Advanced infrastructure | R1 justified an infrastructure need | Profile local GPU/native inference before opt-in remote workers; demonstrate denial and failure controls |
| 8 Research interface | Approved workflow and API boundary | Accessible UI and scoped API. R2 gate. SDK after contract stability and maintainer review |
| 9 Publication and release | License, rights, security review and reproducibility evidence | Authorized release/report with negative results and reproducibility bundle. R3 SDK conditional |

At each transition, the owner reviews the linked evidence and records scope and approval. See [release criteria](RELEASE_CRITERIA.md) and [human approval](../governance/HUMAN_APPROVAL_POLICY.md).
