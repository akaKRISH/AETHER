# Supply chain security

Every introduced crate, Python dependency, CI action, image, pretrained model and dataset needs an explicit engineering purpose and an owner. Review origin, maintenance, license, update impact, native code and known security advisories. Pin the Rust toolchain and the application lockfile when they become active. Distinguish library development from the distributed CLI's exact dependency inputs. Pin CI actions by reviewed immutable revision and worker images by digest. Freeze task pack inputs, options and artifact types in the protocol.

The controller task registry uses reviewed executable and argument selections. Worker and proposer have no package installation or dependency-update authority. Verify staged artifacts and dependencies against trusted source references before enabling work. Review transitive dependencies, build scripts and any future FFI, and document exceptions and their expiry. A release requires an inventory, vulnerability dispositions, license notices and reproducibility checks for supported build paths. Prioritize requalification after a dependency or base image change.
