# Incident response

In the single-owner environment the project owner coordinates response. Treat an isolation failure, unauthorized action, leaked secret, altered experiment artifact, protected label exposure or unbounded resource use as a suspension trigger for the affected path. Record object identifiers, timeline, expected checks, observed outcomes and trusted artifact digests. Retain safe evidence and avoid copying sensitive content into tickets or chat.

1. Cancel affected campaigns and prevent new dispatch. Confirm process cleanup or isolate the runtime.
2. Revoke exposed credentials and isolate artifacts from verification and export. Identify affected scope and related attempts.
3. Preserve safe logs and protocol, policy and runtime versions. Append corrections and invalidate affected verdicts where scientific evidence is unreliable.
4. Identify the causal control failure, implement a tested correction and review neighboring trust-boundary paths.
5. Resume only after owner review of containment and rerun of the applicable denial, integrity and recovery tests. Document remaining impact and any required independent review.

Use a private disclosure route approved by the owner before accepting external reports. [Repository disclosure policy](../../SECURITY.md)
