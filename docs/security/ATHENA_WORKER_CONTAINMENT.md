# Windows reviewed worker containment

The Windows supervisor configures a new anonymous Job Object before launching a reviewed worker. It sets one second of user-mode CPU time per process and for the whole job, a 64 MiB aggregate commit limit, one active process and kill-on-close. Windows checks CPU consumption periodically and terminates the affected process or job on quota exhaustion. An allocation that would exceed the commit limit fails. The trusted worker waits on a one-byte pipe until the supervisor confirms attachment. Job creation, configuration or attachment failure prevents admission. [Microsoft limit semantics](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) · [Runner source](../../crates/aether-runner/src/windows_worker.rs)

The supervisor admits the running platform image and a fixed worker subcommand with a typed task. It clears the inherited environment, sets a fresh working directory, bounds captured stdout and discards stderr. Cancellation and elapsed wall timeout take precedence when polling the worker result. The supervisor closes the job before joining the output reader and reaps a stopped worker. The controller charges interrupted attempts through its existing lease rules. [Runner](../../crates/aether-runner/src/lib.rs) · [Controller](../../crates/aether-api/src/lab.rs)

The supervisor retains the pinned `win32job` handle owner and uses the already locked Windows bindings for one call to set limits the wrapper cannot express. The job enables no process breakaway. Closing the last job handle terminates attached processes. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

| Control | Verified or outstanding |
|---|---|
| Process count and cleanup | The production one-process job refused a fixture's child launch. A separate two-process test job proved kill-on-close with a running descendant and a delayed marker. |
| Timeout and cancellation | A sleeping fixture wrote a ready marker in its working directory. Timeout and active cancellation returned their respective errors and reaped it before its delayed write. |
| CPU and memory | The busy fixture exited with the Windows quota status. Under the commit cap, a 1 MiB reservation succeeded and a reservation exceeding 64 MiB failed. |
| Environment and registry | A canary inherited by the test supervisor was absent from the worker. Tests rejected an alternate executable and filesystem or URL parameters in the typed task. |
| Filesystem, egress and identity | The worker retains the desktop user's OS identity. Job limits do not restrict filesystem reads, writes or network egress. The fresh working directory only changes relative path resolution. Work that requires OS-level filesystem or network denial awaits a qualified backend. |
| Portability | The qualified build is Windows x64. Linux containment and externally supplied programs require independent review and test evidence. |

The validation host reported Windows Home Single Language. Microsoft supports Windows Sandbox on other Windows editions. AppContainer is a separate Windows isolation mechanism with different launch, identity and permission requirements. Neither mechanism is part of this job profile. The registry runs reviewed built-in algorithms under this profile.
