# Technical assessments

Before accepting a component, explain what it guarantees, predict one valid outcome and one failure, and point to a runnable test once approved. For Phase 1, explain why zip-like pairing needs a length check, show the borrower/owner relationship and trace how a changed manifest is detected. For Phase 2, show which database changes must share a transaction. For Phase 3, interpret a stale lease and why resource limits need OS enforcement. For ECAR, compute a small ranking by hand and identify when STOP is required.

Record the question, answer, correction and revised rationale in the relevant milestone review. Evaluate reasoning with an example the owner has not memorized. [Lesson 1](LESSON_01_CLASSIFICATION_AND_RUST.md)
